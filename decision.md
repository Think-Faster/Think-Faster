## D-003 · Конфигурация стенда в Yandex Cloud

- **Дата:** 17.09.2026
- **Кто:** Александр
- **Вопрос:** управляемые сервисы Yandex Cloud или всё на одной виртуалке
- **Варианты:**
  1. Managed PostgreSQL + Managed Redis + отдельная ВМ под приложение;
  2. одна ВМ, всё в Docker Compose, работает круглосуточно;
  3. одна ВМ, всё в Docker Compose, включается только на тесты и демо.
- **Решение:** вариант 3. Intel Ice Lake, 4 × 100% vCPU, 16 ГБ RAM, 80 ГБ SSD, Ubuntu 22.04, **динамический** публичный IP. PostgreSQL, Redis, FastAPI, фронт и nginx — контейнерами на этой же ВМ. Бэкапы — в Object Storage.
- **Почему:** грант — 5 000 ₽ на весь проект, стенд нужен живым 29.09. По тарифам на 17.09.2026 вариант 1 стоит 4 690 ₽ за 13 дней (грант кончается ровно в день сдачи), вариант 2 — 3 897 ₽ (78% гранта за стенд, которым ночью никто не пользуется), вариант 3 — около 1 452 ₽ при пяти часах работы в день плюс сутки демо. Один Managed PostgreSQL минимальной конфигурации обошёлся бы в 2 700 ₽ — половина гранта за одну базу.
- **Последствия:**
  - стенд не работает круглосуточно; команда обязана выключать ВМ после работы, иначе расчёт не действует;
  - IP меняется при каждом включении — актуальный адрес смотрим в консоли, на демо вешаем домен;
  - полная история 313,5 млн строк в облако не поедет: там только 2025–2026, остальное локально в DuckDB/Parquet;
  - обучение модели идёт на машине Захара, не в DataSphere;
  - пересматриваем, если грант окажется больше 5 000 ₽ или организаторы дадут отдельные ресурсы.
