## Зачем

Прежде чем анализировать данные, команде нужна одна понятная карта: **где и как лежат данные и как таблицы связаны друг с другом**. С ней Гера не тратит время на разбор структуры, а Гриша знает, что отдавать через API.

Алгоритм превышений — первый **детерминированный** расчёт на реальных данных. Он показывает, где показания и журнал аварий согласуются, а где нет. Расхождения — прямой материал для поиска шума и ложных срабатываний.

Схема из ТЗ: [Приложение 1](../docs/ТЗ.md#63-пример-журнала-сработок-приложение-1): журнал записей → канал данных → тег в дереве объектов; тип канала; дерево объектов и систем. Связь тега `МК-…` с деревом объектов в ТЗ **не описана** ([открытые вопросы](../docs/ТЗ.md#10-открытые-вопросы-и-противоречия)).

> ⚠️ БД — **только чтение**. Ничего не изменять и не удалять, тяжёлые запросы по всей истории не запускать без ограничения периода.

## Что сделать

### 1. Инвентаризация

- [ ] СУБД и версия, схемы.
- [ ] Список таблиц: число строк, размер, период данных (минимальная и максимальная дата).
- [ ] Индексы и партиции — по каким полям быстро фильтровать.

### 2. Описание таблиц

- [ ] Для каждой таблицы — поля:

| Поле | Тип | Смысл | Пример | Доля пустых | Ключ |
|---|---|---|---|---|---|

### 3. Связность таблиц

- [ ] Первичные и внешние ключи — объявленные в БД и фактические (по совпадению значений).
- [ ] **ER-диаграмма** в формате Mermaid — GitHub отрисовывает её прямо в `.md`.
- [ ] Проверка целостности, с количеством:
  - [ ] записи журнала с каналом, которого нет в реестре каналов;
  - [ ] каналы без единой записи;
  - [ ] теги, которых нет в дереве объектов;
  - [ ] дубли ID.
- [ ] Расшифровка тега `МК-x.x.x.x.x.x`: что означает каждый уровень, если это можно понять по данным.

### 4. Как хранятся значения

- [ ] Аналоговые (температура) и дискретные (дым, движение, контакт: 0/1 или состояния) — как различаются.
- [ ] Частота записи: периодически или только при изменении значения.
- [ ] Формат даты, часовой пояс, десятичный разделитель (в ТЗ `25,00` — через запятую).
- [ ] **Где фиксируются аварийные события**: отдельный журнал событий, флаг, тип события («Норма», «Предупреждение», «Авария» — как в Приложении 2) — и как такая запись связана с показанием канала.
- [ ] Хранятся ли в БД уставки — пороговые значения каналов.

📌 **К 13:00 — отдать Гере черновик шагов 1–4.**

### 5. Алгоритм превышения аварийных порогов

**Идея:** определить аварийный порог по тому, при каких значениях журнал фиксирует аварию, и сравнить все показания с этим порогом.

- [ ] **Порог.** Для каждого типа канала (и для отдельных каналов, если отличаются):
  - если в БД есть уставка — брать её;
  - если нет — вывести из журнала: значение показания в момент аварийной записи; как агрегировать (минимум, медиана), зафиксировать и обосновать.
- [ ] **Сопоставление.** Аварийная запись ↔ показание канала: по ИД канала и времени в окне ± N минут. Окно — параметр.
- [ ] **Классификация.** Каждый случай отнести к одной из групп:

| Группа | Условие | Что это может значить |
|---|---|---|
| A. Подтверждённые | значение выше порога **и** есть аварийная запись | реальная авария |
| B. Без записи | значение выше порога, аварийной записи **нет** | пропуск в журнале или выброс |
| C. Запись без превышения | аварийная запись есть, значение **ниже** порога | кандидат в шум или ложное срабатывание → Гере |

- [ ] **Направление порога.** Не у всех каналов авария — это «выше»: учесть нижние пороги и дискретные каналы (для них превышение — переход в аварийное состояние).
- [ ] **Параметры** запуска: тип канала, период, окно сопоставления.
- [ ] **Реализация** — SQL-запрос или Python-скрипт, только чтение.
- [ ] **Пробный прогон**: температура (тип 12) за 1 месяц → количество случаев в группах A, B, C и по 3–5 примеров в каждой.

### 6. Передать Гере

- [ ] Таблицу порогов и списки групп B и C — для сверки со справочником датчиков (TF-1, шаг 4).

## Готово, когда

- [ ] Гера и Гриша понимают структуру БД по документу без вопросов к Захару.
- [ ] Есть ER-диаграмма и проверка целостности с цифрами.
- [ ] Известно, где хранятся аварийные события и как они связаны с показаниями.
- [ ] Алгоритм запускается с параметрами и выдаёт группы A, B, C; пробный прогон описан.
