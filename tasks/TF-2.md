## Зачем

По ТЗ оцениваются интуитивность интерфейса, расположение связанных блоков рядом, объективность диаграмм и выступление на питче ([ТЗ, раздел 8](../docs/ТЗ.md#8-критерии-оценки)). Чтобы делать макеты не с нуля:

- **презентация** должна выглядеть своей для экспертов Правительства Москвы;
- **интерфейс** должен опираться на то, как устроены реальные системы диспетчеризации и техобслуживания.

Экраны, которые требует ТЗ ([раздел 2.6](../docs/ТЗ.md#26-пользовательский-интерфейс-10) и [сценарии](../docs/ТЗ.md#7-пользовательские-сценарии-12)):

1. дашборд с уровнями риска;
2. интерактивная карта с проблемными зонами;
3. журнал прогнозов с историей и результатами отработки;
4. уведомления о критических инцидентах;
5. фиксация решения диспетчера с причиной из справочника.

Текущий интерфейс заказчика: [Приложение 2](../docs/ТЗ.md#64-пример-формы-журнала-технологических-событий-приложение-2).

## Что сделать

### Часть А. Презентации проектов Правительства Москвы

- [ ] Найти **не меньше 5** презентаций или публичных страниц городских проектов в сфере ЖКХ, городского хозяйства и цифровизации. Где искать: mos.ru, сайты департаментов (ЖКХ, ДИТ), материалы «Лидеров цифровой трансформации», питчи победителей прошлых ЛЦТ.
- [ ] Отдельно разобрать **обложку нашего ТЗ** — это прямой ориентир по стилю конкурса: фиолетовый градиент, логотипы партнёров в шапке.
- [ ] Выписать:
  - **палитру** — hex-коды основных цветов;
  - **шрифты** — каким набраны заголовки и текст, проверить фирменный шрифт города;
  - **структуру слайдов** — порядок блоков: проблема → решение → эффект → …;
  - **как подают цифры и эффект** — крупные числа, графики, «было / стало»;
  - **правила логотипов** — где стоят, в каком порядке.
- [ ] Итог: список «делаем так» и «так не делаем».

### Часть Б. Интерфейсы техобслуживания и диспетчеризации

- [ ] Найти **не меньше 8** интерфейсов. Хотя бы по одному из каждой группы:
  - диспетчерские системы мониторинга (SCADA / HMI);
  - системы техобслуживания и ремонта (ТОИР / CMMS / EAM);
  - городские диспетчерские ЖКХ;
  - ГИС-карты инженерных сетей;
  - системы оповещений и работы с инцидентами.
- [ ] Для каждого — карточка:

| Поле | Что писать |
|---|---|
| Название, ссылка | |
| Группа | из списка выше |
| Скриншот | файл в `docs/designs/TF-2-img/` |
| Экраны | какие есть |
| Функции | что пользователь там делает |
| Структура | навигация: меню, вкладки, панели |
| **Берём** | что подходит нам и для какого из 5 экранов |
| **Не берём** | что неудобно или лишнее |

- [ ] **Сводка функционала** — таблица «функция × приложения»: что встречается почти везде. Например: список событий с фильтрами, карточка объекта, цветовые статусы, подтверждение тревоги оператором (квитирование), история.
- [ ] **Типовая структура** такого приложения — схема навигации: какие разделы, что на главном экране.

### Часть В. Сопоставление с нашими экранами

- [ ] Для каждого из 5 экранов ТЗ — 2–3 лучших референса и что конкретно берём.
- [ ] Разобрать текущий интерфейс заказчика (Приложение 2): что в нём мешает диспетчеру, что сохранить привычным.

## Готово, когда

- [ ] Не меньше 5 презентаций, есть палитра в hex, шрифты и структура слайдов.
- [ ] Не меньше 8 интерфейсов из разных групп, у каждого заполнено «берём / не берём».
- [ ] У каждого из 5 наших экранов есть референсы.
- [ ] Скриншоты лежат в репозитории, ссылки рабочие.
