## Зачем

По ТЗ решение — отдельный сервис с REST API, серверная часть на Linux, СУБД PostgreSQL 12+ ([ТЗ, разделы 2.7–2.8](../docs/ТЗ.md)). Прототип сдаётся ссылкой. Если сервер и каркас API готовы заранее, результаты Геры и Захара можно сразу подключать, а не ждать инфраструктуру в конце.

## Что сделать

### 1. Железо

- [ ] Характеристики сервера: CPU, RAM, диск, GPU, ОС и версия.
- [ ] Хватит ли места под данные: объём данных уточнить у Геры (TF-1, шаг 1).
- [ ] Что уже установлено и запущено.

### 2. Доступы

- [ ] Персональные учётные записи для участников вместо общего `user1`, вход по SSH-ключам.
- [ ] Паролей, ключей и токенов в репозитории нет — только в личной передаче или переменных окружения.
- [ ] Обновить `docs/instructions/how to connect.md`: как получить доступ и подключиться.

### 3. Базовое окружение

- [ ] Docker и Docker Compose.
- [ ] Python нужной версии.
- [ ] PostgreSQL 12+ (требование ТЗ) — если БД на этом сервере, зафиксировать версию.

### 4. Оболочка API

Каркас сервиса без реальной логики — ответы-заглушки, чтобы фронт и аналитика могли подключаться к стабильным адресам.

- [ ] Стек — на выбор, зафиксировать в документе. Удобный вариант — FastAPI: документация OpenAPI / Swagger генерируется автоматически.
- [ ] Общее:
  - [ ] `GET /health` — сервис жив;
  - [ ] префикс версии `/api/v1`;
  - [ ] настройки через переменные окружения, в репозитории только `.env.example`;
  - [ ] логирование запросов (ТЗ требует журналирования действий пользователей);
  - [ ] CORS для будущего фронта;
  - [ ] Dockerfile и команда запуска.
- [ ] Эндпоинты-заглушки по сущностям ТЗ, с примером JSON-ответа:

| Метод | Адрес | Что отдаёт | Основание в ТЗ |
|---|---|---|---|
| GET | `/api/v1/channel-types` | типы каналов | Приложение 1 |
| GET | `/api/v1/channels` | реестр каналов | Приложение 1 |
| GET | `/api/v1/objects` | дерево объектов и систем | Приложение 1 |
| GET | `/api/v1/readings?channel_id&from&to` | показания канала за период | §6, §13 |
| GET | `/api/v1/events` | журнал событий | §6, Приложение 2 |
| GET | `/api/v1/thresholds` | справочник порогов (из TF-1) | — |
| GET | `/api/v1/predictions` | прогнозы: вероятность, горизонт, локация, тип | §5, §6 |
| POST | `/api/v1/decisions` | решение диспетчера с причиной из справочника | §12 |

- [ ] Поля ответов пока условные; после TF-1 и TF-3 привести к реальной структуре.
