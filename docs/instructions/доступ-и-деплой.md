# Стенд в Yandex Cloud: как пользоваться

Инструкция для всей команды. Разбор площадки и расчёт денег — в [docs/infra/yandex-cloud.md](../infra/yandex-cloud.md).

## 🔴 Правило первое: стенд живёт только на время работы

**У нас грант 5 000 ₽ и больше ничего.** Стенд нужен живым 29.09, в день сдачи. Круглосуточно работающая ВМ съедает ~3 900 ₽ за 13 дней — то есть почти весь грант на то, чтобы ночью никто ею не пользовался.

Поэтому:

- **Включил — поработал — выключил.** Не «потом выключу», а сразу после того, как закончил.
- Закончил тест — выключи, даже если через два часа планируешь ещё раз.
- Не уверен, нужен ли стенд кому-то ещё, — **спроси в чате, прежде чем выключать**, но не оставляй «на всякий случай» на ночь.
- Разработка и отладка идут **локально**, в том же Docker Compose. Облако — только для проверки «работает ли снаружи» и для демо.
- Обучение модели и тяжёлые расчёты — **на своей машине**, не на стенде.

Выключенная ВМ всё равно стоит денег за диск — около 38 ₽ в сутки. Это нормально, это цена того, что данные не надо заливать заново. А вот включённая и забытая — 300 ₽ в сутки.

## Кто что может

| Кто | Права |
|---|---|
| Александр | владелец облака: создаёт и удаляет ресурсы, выдаёт доступы, смотрит биллинг |
| Гриша | администратор ВМ: разворачивает сервисы, перезапускает, включает и выключает ВМ |
| Гера, Захар, Даша | доступ по SSH на чтение логов и запуск проверок; включение и выключение ВМ |

Создавать и удалять ресурсы в облаке может только Александр. Если нужен ещё один диск, адрес или вторая ВМ — в чат, не своими руками: каждый новый ресурс — это деньги из общего гранта.

## Как получить доступ

1. Сгенерируй SSH-ключ, если его нет:

```bash
ssh-keygen -t ed25519 -C "имя@think-faster"
```

2. Пришли Александру **публичную** часть — файл `~/.ssh/id_ed25519.pub`. Приватный ключ не пересылается никому и никогда.
3. В ответ получишь имя пользователя и текущий IP стенда.

> ⚠️ У стенда **динамический** IP: при каждом включении адрес меняется. Актуальный адрес — в чате команды или в консоли облака. Так дешевле: статический адрес тарифицируется даже когда ВМ выключена.

## Включить и выключить стенд

Через консоль Yandex Cloud: **Compute Cloud → виртуальные машины → три точки → Запустить / Остановить**.

Через CLI, если установлен `yc`:

```bash
yc compute instance start think-faster-stand
```

```bash
yc compute instance stop think-faster-stand
```

После запуска адрес смотрим так:

```bash
yc compute instance get think-faster-stand --format json
```

Сервисы поднимаются сами при старте ВМ. Подождать 1–2 минуты после того, как консоль покажет `RUNNING`.

## Подключиться и посмотреть, что происходит

```bash
ssh имя@АДРЕС_СТЕНДА
```

```bash
docker compose ps
```

```bash
docker compose logs -f --tail=100 api
```

```bash
df -h
```

Перезапустить один сервис:

```bash
docker compose restart api
```

## Выкатить изменения

Только из ветки `main`, только после того, как локально всё поднялось и прошли проверки.

```bash
ssh имя@АДРЕС_СТЕНДА
```

```bash
cd ~/think-faster && git pull && docker compose up -d --build
```

```bash
curl -sS https://АДРЕС_СТЕНДА/health
```

Если `/health` не отвечает — откатываемся, а не чиним на живую:

```bash
git reset --hard HEAD~1 && docker compose up -d --build
```

## Чего делать нельзя

- ❌ Оставлять ВМ включённой на ночь или на выходные.
- ❌ Создавать новые ресурсы в облаке — ВМ, диски, статические адреса, управляемые базы. Managed PostgreSQL стоит 2 700 ₽ за две недели, это половина гранта.
- ❌ Привязывать к аккаунту банковскую карту, пока не выяснено, что происходит при исчерпании гранта.
- ❌ Класть секреты в репозиторий. В git — только `.env.example`; реальные значения живут в `.env` на стенде и передаются лично.
- ❌ Открывать наружу порты, кроме 443 и SSH. Базу и Redis наружу не публикуем никогда.
- ❌ Выкатывать напрямую в день сдачи без проверки. 28 и 29 сентября — **только откат, никаких новых фич на стенде**.
- ❌ Удалять диск или снимки, «чтобы сэкономить». Данные дороже.
