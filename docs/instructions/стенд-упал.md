# Стенд упал — что нажать

Одна страница на случай ЧП. Подробности — в [доступ-и-деплой.md](доступ-и-деплой.md).

**Сначала спроси в чате, не выключил ли кто-то ВМ намеренно.** Это самая частая причина.

## 1. Сайт не открывается

```bash
yc compute instance get think-faster-stand --format json
```

- Статус `STOPPED` → запустить, подождать 2 минуты.
- Статус `RUNNING`, но не отвечает → зайти по SSH и посмотреть `docker compose ps`.
- **Адрес мог смениться**: у стенда динамический IP, после каждого включения он новый.

## 2. Сервис не отвечает, ВМ жива

```bash
docker compose ps && docker compose logs --tail=50 api
```

```bash
docker compose restart api
```

Не помогло — `docker compose up -d --build`. Всё ещё нет — откат на предыдущий коммит.

## 3. Кончилось место

```bash
df -h && docker system df
```

```bash
docker system prune -f
```

Чаще всего место съедают старые образы и логи. **Диск не расширять без Александра** — это деньги из гранта.

## 4. База не поднимается

```bash
docker compose logs --tail=100 db
```

- Не хватает места → пункт 3.
- Повреждены данные → восстановить из последнего дампа в Object Storage.
- **Данные не удалять.** Перелить историю заново — это часы.

## 5. Не пускает по SSH

- Проверь, что адрес актуальный (пункт 1).
- Проверь, тот ли ключ: `ssh -i ~/.ssh/id_ed25519 имя@АДРЕС`.
- Не помогло — через консоль облака, серийная консоль ВМ.

## 6. Кончился грант

Признак: ресурсы остановились сами, в консоли предупреждение по биллингу.

- **Карту не привязывать** — это решение Александра, не твоё.
- Переходим на план Б: локальный запуск из чистого клона, демо с ноутбука.

```bash
docker compose up -d --build
```
